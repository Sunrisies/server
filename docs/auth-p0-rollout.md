# P0 鉴权修复上线说明

公开注册返回 403，不访问数据库。内部创建用户只绑定 USER 角色，缺失时事务回滚，不能自动授予管理员。已存在的管理员不会自动降级。

移除启动配置、JWT claims/key、密码登录 JWT、邮箱登录 JWT/验证码以及未实现登录分支的请求日志。JwtSettings Debug 自动脱敏。JWT_SECRET 必填，至少 32 字节，拒绝示例占位密钥；缺失时进程启动失败。

## 上线顺序

1. 备份数据库，确认合法管理员名单；审计现有 SUPER_ADMIN 用户及角色绑定，人工确认可疑账户后禁用。不要直接删除所有管理员。
2. 在服务器密钥管理或受限环境文件中生成并替换 JWT_SECRET：`openssl rand -hex 32`。不要提交、打印到日志或发送到聊天。所有实例使用同一新密钥。
3. 部署修复版本并重启所有后端实例；旧密钥不可作为备用验证密钥继续使用。旧 JWT 会立即失效，所有用户需重新登录；使用 JWT_SECRET 的剪贴板令牌也会失效。
4. 检查无登录 POST /api/v1/auth/register 返回 403，原令牌访问受保护用户接口返回 401，新登录和管理操作正常。检查新日志不含 JWT_SECRET 或 access_token。
5. 对历史日志及副本限制访问，并按保留策略清理泄漏内容；轮换密钥仍必须执行。

本地修复及测试不会改变线上密钥、账户或运行实例。只有完成上述上线步骤，线上 P0 才算关闭。
