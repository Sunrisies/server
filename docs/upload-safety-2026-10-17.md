# 七牛上传线程与图片资源限制修复

仅处理上传线程阻塞、图片解码限制和临时文件清理；没有修改统计功能、公开页面缓存或其他管理功能。

## 实现

- Multipart 文件分块通过 Tokio 异步写入磁盘，完成并 flush 后才开始图片处理。
- 临时目录/文件创建、图片解码/缩放/编码、七牛同步 SDK 上传在 `web::block` 工作线程执行。请求运行线程不再直接执行这些耗时操作。
- 进程内两个上传槽位由所有 Actix worker 共享，包含接收、处理和上传；等待槽位超过2秒返回503，提示稍后重试。该限制仅作用于上传，不限制文章读取。
- 处理/上传任务拥有槽位及 `NamedTempFile`，取消请求不会提前释放后台任务仍在使用的资源。任务返回后自动清理；接收错误、空文件、超限、解码错误、七牛上传错误同样由文件所有权保证清理。
- 临时文件清理覆盖进程内的正常返回、错误返回、请求取消和异常展开。强制结束进程/断电无法执行析构；现有 release `panic=abort` 也属于进程终止，不承诺该场景自动清理。
- 按真实格式解码，仅接收现有前端支持的PNG/JPEG/WebP。解码宽高各不超过8192，解码器分配预算64MiB。预算并非整个进程RSS上限；并发槽位同时约束处理任务数。
- 保持原输出图片格式与上传返回字段。超出1920×1080的图片等比缩小，小图片不再被放大。原七牛图片接收上限20MiB不变，后台界面原有10MiB限制不变；超过后端字节上限返回413。
- 文件写入刷新/关闭后，后台任务才重新读取，避免上传尚未写完的内容。
